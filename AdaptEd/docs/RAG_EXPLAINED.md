# RAG простыми словами

Объяснение без терминов: как система определяет тему задачи и находит нужный кусок учебника.

## Главная идея

Компьютер не понимает слова — он понимает **числа**. Весь фокус RAG в том, чтобы превратить смысл текста в **набор координат**, как точку на карте.

Представь огромную карту, где у каждого текста есть своё место. Похожие по смыслу тексты стоят рядом (как дома на одной улице), а разные — далеко (в разных городах). «Квадратное уравнение» и «дискриминант» — соседи. «Квадратное уравнение» и «треугольник» — в разных концах карты.

Только карта не плоская (2 координаты) и не объёмная (3), а **1536-мерная** — у каждой точки 1536 координат. Представить это глазами нельзя, но математика работает одинаково в любом числе измерений. Этот набор из 1536 чисел и называется **вектор** (или эмбеддинг).

---

## 1. Откуда берутся координаты (HTTP-запрос, ключ, батч)

Сами мы не умеем превращать текст в 1536 координат — это делает специально обученная нейросеть на чужом сервере.

- **Куда отправляем.** NeuroAPI — сервис в интернете. У него есть «окошки»: одно (`/chat/...`) отвечает текстом (наш ИИ-помощник), другое (`/embeddings`) принимает текст и возвращает 1536 чисел. **HTTP-запрос** — это просто «послать данные на сервер и получить ответ» (так же браузер открывает страницу).
- **Что за ключ.** Сервис платный, поэтому требует пароль-пропуск — это **ключ** (`PROXYAPI_KEY`, строка вида `sk-...`). Без него сервер не ответит.
- **Почему тем же ключом.** Чат уже ходит на NeuroAPI с этим ключом, и через тот же аккаунт доступно окошко эмбеддингов. Значит, не нужен второй сервис/платёж/пароль — всё по одному пропуску.
- **Батч (пачка).** Можно попросить координаты для одного текста, а можно за один заход отправить сразу 12 текстов и получить 12 наборов координат. Один поход на сервер вместо двенадцати — быстрее и дешевле.

> Аналогия: ключ — абонемент в спортзал. Там есть тренажёры (чат) и бассейн (эмбеддинги), по одному абонементу пускают в обе зоны. Батч — привёл 12 друзей разом, а не водил по очереди.

## 2. Нарезка учебника (три шага)

**Шаг А — структура из книги.** Из текста PDF ищем заголовки: `Глава …`, `§ …`, `Параграф …`, `3.1 …`. **Глава** — группа (родитель), **параграф/§** — узкая тема фрагмента. Названия не придумываем — берём из учебника.

**Шаг Б — нарезка внутри параграфа.** Текст каждого параграфа режем на кусочки ≈700 символов (по абзацам). У всех кусков одного § одна и та же тема.

**Шаг В — превращение в вектор.** Каждый кусочек отдельно отправляем на сервер (шаг 1) и получаем его 1536 координат.

Итог: учебник → параграфы из оглавления → кусочки текста → у каждого свой вектор, тема = § из книги.

> Аналогия: книгу режем по параграфам (как в оглавлении), внутри параграфа — на карточки, и каждой карточке даём адрес на карте смыслов.

---

## 3. Матрица и умножение

**Матрица** — просто таблица чисел: одна строка = один кусочек, в строке 1536 чисел (его координаты).

```
            коорд.1  коорд.2  ...  коорд.1536
кусочек 1 [  0.01    -0.03   ...    0.02   ]
кусочек 2 [ -0.05     0.07   ...    0.01   ]
...
кусочек N [  0.02     0.00   ...   -0.04   ]
```

Вопрос ученика тоже превращаем в вектор — ещё одну строчку из 1536 чисел.

Чтобы понять, к какой строке таблицы вопрос ближе, можно сравнивать с каждой по очереди. Но «умножение матрицы на вектор» делает это **за одно действие сразу со всеми строками**. На выходе — столбик «баллов схожести», по одному на кусочек. Компьютер считает это молниеносно (5000 кусочков ≈ 2.8 миллисекунды).

> Аналогия: вместо опроса каждого из N человек по очереди — задаёшь вопрос всему залу разом и сразу получаешь оценку от каждого.

## 4. Угол или длина? — Угол

У вектора есть **длина** (насколько большой) и **направление** (куда смотрит). Для смысла важно **направление**: два текста про квадратные уравнения «смотрят в одну сторону», даже если один длинный, а другой короткий. Длина зависит от объёма текста, а не от темы, поэтому её убираем.

Меру «насколько одинаково смотрят два вектора» даёт **косинус угла**:

- угол 0° (одинаковое направление) → косинус = **1** → один смысл;
- угол 90° (перпендикулярны) → косинус = **0** → не связаны;
- **чем ближе к 1 — тем похожее.**

Хитрость: заранее «подрезаем» все векторы до длины 1 (нормализация). После этого сравнение направлений превращается в простое умножение — поэтому быстро.

В интерфейсе косинус показан в процентах: «73%» рядом с темой = косинус 0.73 = довольно похоже.

> Аналогия: два человека показывают руками направление. Неважно, у кого рука длиннее — важно, в одну ли сторону. В одну → «100%», один вверх/другой вбок → «0%».

---

## Всё вместе одной фразой

> Учебник режем на карточки → каждую через интернет-сервис (по платному ключу) превращаем в точку на «карте смыслов» (1536 координат) → складываем все точки в таблицу → вопрос ученика тоже делаем точкой → одним умножением находим, куда вопрос «смотрит» так же, как карточки → ближайшая по направлению (косинус ближе к 1) и есть нужная тема.
