## 1. Главная идея проекта (запомни наизусть)

**Цель:** замкнутый цикл персонализации:

```
задание → ответ ученика → анализ ошибки → обновление профиля → следующее задание по слабой теме
```

**Новизна (честно):** не «ещё один сайт с тестами», а связка:
- когнитивный профиль ученика;
- мультиагентная серверная логика;
- LLM для генерации заданий и чата;
- RAG для темы и контекста из учебника;
- ролевые кабинеты (ученик / учитель / админ).

**Формулировка для защиты:**
> «Клиент-серверная система с REST API, PostgreSQL и контуром агентов + LLM/RAG для адаптивного обучения.»

## 2. Архитектура и стек

### Из чего собрано

| Слой | Технология | Где в проекте |
|------|------------|---------------|
| Frontend | React + TypeScript + Vite | `AdaptEd/frontend/` |
| Backend | Python + FastAPI | `AdaptEd/backend/app.py` |
| БД | PostgreSQL + SQLAlchemy | `utils/db.py`, `models/` |
| LLM | NeuroAPI (OpenAI-совместимый), `gpt-4o-mini` | `services/assistant.py` |
| Деплой | Railway (фронт, бэк, БД отдельно) | переменные окружения |

### Путь одного запроса

```
Браузер (React)
  → HTTP + JSON
  → заголовок Authorization: Bearer <токен>
  → FastAPI (роутер routes/*.py)
  → проверка токена и роли (Depends)
  → оркестратор / сервисы
  → PostgreSQL и/или вызов NeuroAPI
  → JSON-ответ обратно на фронт
```

**Точка входа бэка:** `app.py` — подключает роутеры (`auth`, `agents`, `homework`, `tests`, `rag`, …).

**Главный сценарий ученика (адаптивное задание):**
1. `AdaptiveTask.tsx` → `POST /agents/generate-adaptive-task` (LLM генерирует задачу)
2. Ученик отвечает → `POST /agents/submit-task`
3. Оркестратор: проверка → ошибка → профиль → сообщение наставника
4. UI показывает результат и рекомендацию

> **Важно:** старый `TaskGeneratorAgent` с банком «15+8» **удалён**. Генерация только через LLM (`/generate-adaptive-task`).

## 3. CORS — зачем и что значат слова

### Проблема

Фронт и бэк на Railway часто на **разных доменах** → для браузера это **cross-origin** (чужой origin).

**Origin** = протокол + домен + порт, например:
- `https://фронт.up.railway.app`
- `http://localhost:5173`

**Same-origin** — тот же origin. **Cross-origin** — другой.

### Кто блокирует

Не FastAPI, а **браузер**. Без разрешения бэка он **не отдаёт JavaScript ответ** с другого домена (защита от кражи данных с чужих сайтов).

### CORS-middleware

Прослойка в `app.py`, которая на каждый ответ добавляет заголовки «с какого фронта можно»:

| Заголовок | Смысл |
|-----------|--------|
| `Access-Control-Allow-Origin` | Разрешённый сайт-источник |
| `Access-Control-Allow-Methods` | GET, POST, PUT, … |
| `Access-Control-Allow-Headers` | Authorization, Content-Type, … |
| `Access-Control-Allow-Credentials` | Можно слать токен |

**Preflight** — предварительный вопрос браузера «можно ли так делать?»  
**OPTIONS** — HTTP-метод для этого вопроса (без тела запроса).

Цепочка: `OPTIONS` → бэк «да» → `POST` с токеном → ответ с `Allow-Origin` → React видит данные.

**Код:** `app.py` — `CORSMiddleware` + `_force_cors_headers`.

**На защите:**
> «CORS не заменяет авторизацию — это первый фильтр браузера. Без него фронт на другом домене не получит ответ API, даже если бэк отработал.»

## 4. Мультиагентная система

### Это не «пять нейросетей»

**Программные агенты** — классы с единым методом `process(input) → output`. Координирует **оркестратор** (`agents/orchestrator.py`).

| Агент | Файл | Задача |
|-------|------|--------|
| `ErrorAnalyzerAgent` | `error_analyzer_agent.py` | тип ошибки |
| `ProfilerAgent` | `profiler_agent.py` | когнитивный профиль |
| `MentorAgent` | `mentor_agent.py` | мотивационное сообщение |
| `TeacherAnalyticsAgent` | `teacher_analytics_agent.py` | сводки для учителя |
| `AgentOrchestrator` | `orchestrator.py` | вызывает агентов по цепочке |

**LLM** подключён точечно: генерация заданий, чат, подсказки, классификация ошибок (нечисловые ответы).

### Сценарий: ученик отправил ответ

Файл: `orchestrator.py` → `process_task_submission`

```
1. Проверка ответа (math_answers_equal / verified_is_correct)
2. TaskAttempt — запись попытки
3. Если неверно → ErrorAnalyzerAgent
4. ProfilerAgent — обновить профиль (mastery, error_frequency, …)
5. MentorAgent — сообщение ученику
6. Вернуть всё одним JSON на фронт
```

Эндпоинт: `POST /agents/submit-task` в `routes/agents.py`.

**На защите:**
> «Агенты разделяют ответственность: профиль, ошибки, мотивация — детерминированная логика; генерация текста — LLM. Оркестратор связывает шаги в один сценарий.»

## 5. Когнитивный профиль и адаптация

### Что хранится

Pydantic-модель `CognitiveProfile`, в БД — JSON в поле `payload` (таблица через `personalization_store.py`).

Ключевые поля:

| Поле | Смысл |
|------|--------|
| `task_history` | история попыток |
| `topic_mastery` | «знание» по темам, 0…1 |
| `error_frequency` | сколько раз каждый тип ошибки |
| `accuracy_rate` | % верных от всех попыток |
| `level`, `points` | геймификация |
| `current_emotional_state` | уверен / фрустрация / … |
| `progress_history` | статистика по дням |

### Формула mastery (важно знать цифры)

Файл: `profiler_agent.py` → `_update_topic_mastery`

- новая тема стартует с **0.5**
- верный ответ: **+0.05** (макс 1.0)
- неверный: **−0.03** (мин 0.0)

Асимметрия: знание растёт чуть быстрее, чем падает.

### Как выбирается следующая тема

`routes/agents.py` → `generate_adaptive_task`:

- темы с `mastery < 0.7` — слабые;
- берётся **самая слабая**;
- LLM генерирует задание по этой теме (+ опционально интересы ученика).

### Сохранение в БД

Профиль в **памяти** (`ProfilerAgent.profiles`) + **батчинг** (`utils/batched_saver.py`): сброс в PostgreSQL раз в ~5 сек или по 10 изменений. При shutdown — `flush`.

**Ограничение прототипа:** рассчитано на один воркер; при нескольких процессах — рассинхрон.

## 6. ErrorAnalyzerAgent — гибрид (вариант B)

Файл: `agents/error_analyzer_agent.py`

### Типы ошибок (`ErrorTag`)

| Код | По-русски |
|-----|-----------|
| `carelessness` | невнимательность, описка |
| `calculation_error` | арифметика |
| `missing_formula` | не тот метод / формула |
| `concept_confusion` | не понял тему |
| `logic_gap` | пропущен шаг, второй корень, логика |

### Логика (гибрид)

```
Оба ответа — числа?  → эвристики по разнице (без LLM)
Иначе                → LLM, строгий JSON с одним тегом
LLM недоступен/мусор → откат на эвристики
```

**Почему так:** для `41` vs `42` разница чисел осмысленна; для `1` vs `1<x<1.5` — нет.

**LLM:** промпт с задачей, ответами и списком тегов → `{"error_type": "...", "justification": "..."}`. Парсер `_parse_llm_json`, проверка тега в `_VALID_TAGS`.

**Отключить LLM на демо:** `ERROR_ANALYSIS_USE_LLM=0`.

### Куда идёт результат

- `error_frequency` в профиле;
- `suggested_remediation` на экран ученика (`AdaptiveTask.tsx`);
- аналитика учителя (типовые ошибки).

**На защите:**
> «Гибрид: скорость и воспроизводимость для чисел; семантика для интервалов и уравнений через LLM с валидацией тега и фолбэком.»

## 7. LLM-интеграция

Файл: `services/assistant.py`

### Провайдер

Переменная `ASSISTANT_PROVIDER` или автовыбор по ключам:
1. NeuroAPI (`PROXYAPI_KEY`) — основной
2. Hugging Face — запасной
3. Локальная модель — только если явно `local`

Метод `_generate`: каскад с фолбэком; при 429 — retry с задержкой.

### Где используется LLM

| Сценарий | Эндпоинт / метод |
|----------|------------------|
| Адаптивное задание | `POST /agents/generate-adaptive-task` |
| Чат-помощник | `routes/assistant.py` |
| Подсказка hint | `assistant.hint()` + контекст RAG |
| Классификация ошибки | `ErrorAnalyzerAgent._classify_with_llm` |
| Разбор теста | `routes/tests.py` (feedback) |

### Генерация задания

Промпт просит **только JSON** (вопрос, ответ, объяснение, тема). Правила: без LaTeX, дроби `(3x-5)/2`, разнообразие типов задач.

## 8. RAG — кратко (+ подробно в отдельном файле)

**Полное объяснение:** [RAG_EXPLAINED.md](./RAG_EXPLAINED.md)

### Зачем

- Определить **тему** задачи (не «общая математика»).
- Дать **контекст из учебника** в подсказках.

### Как устроено технически

1. Текст → вектор 1536 чисел (`text-embedding-3-small`, NeuroAPI `/embeddings`).
2. Хранение: таблица `rag_chunks`, вектор в JSON (без pgvector на Railway).
3. Поиск: numpy, нормализация строк → `matrix @ query_vector` → top-k по косинусу.
4. Классификация темы — **гибрид** в `resolve_specific_topic` (`routes/agents.py`):
   - символьные паттерны (`x^2`, `|`, `√`, …);
   - ключевые слова;
   - RAG (семантика);
   - fallback «общая математика».

### База знаний в UI

Вкладка **«База знаний»** в **админ-панели** (`AdminPanel.tsx` + `RagKnowledgeBase.tsx`).

Действия админа:
- **Засеять базовые темы** — 12 тем школьной математики (`source=taxonomy`);
- **Загрузить PDF** — нарезка на фрагменты, эмбеддинги;
- **Добавить текст вручную**;
- удалить источник / очистить индекс.

| Термин в UI | Значение |
|-------------|----------|
| Эмбеддинги | текст → вектор; «Доступны» = API-ключ работает |
| Фрагмент (chunk) | кусок текста + его вектор |
| Индекс | все фрагменты, готовые к поиску |
| Источник (source) | откуда фрагменты: taxonomy, PDF, ручной текст |
| Проиндексировать | превратить текст в векторы и сохранить |

**Почему не pgvector:** на текущем Railway PostgreSQL расширение недоступно; numpy достаточно для прототипа.

## 9. Авторизация и RBAC

### Роли

`student`, `teacher`, `parent`, `admin`

### Токен

Самописный формат `payload.signature` (HMAC-SHA256), не библиотека JWT.  
Файл: `utils/auth_service.py` → `generate_token`, `get_user_from_token`.

В каждом запросе: `Authorization: Bearer <токен>`.

### RBAC

`routes/auth.py`:
- `get_current_user` — кто ты;
- `require_roles("teacher", "admin")` — кому можно эндпоинт;
- `assert_can_view_user_data` — ученик видит только себя.

### Слабое место (сказать честно)

Пароли: **SHA-256 без соли** (`hash_password`). Для продакшена нужен **bcrypt/argon2**.

## 10. База данных

- **SQLAlchemy** + PostgreSQL (`DATABASE_URL`).
- Пользователи: таблица `users`.
- Профиль: `cognitive_profiles.payload` (JSON).
- RAG: `rag_chunks` (topic, text, source, embedding JSON).
- Домашка, тесты, материалы — отдельные таблицы/модели.

**Почему JSON для профиля:** гибкая вложенная структура без миграции на каждое новое поле.

## 11. Проверка ответов и тесты

Модуль: `utils/answer_parse.py` — `math_answers_equal`, интервалы, дроби.

**Тесты** (`routes/tests.py`):
- типы вопросов: single, multiple, numeric, text;
- баллы: `earned_points` / `max_points` → `score_pct`;
- результат прокидывается в оркестратор с `verified_is_correct` (профиль не переоценивает ответ).

**Домашка** — отдельный большой модуль `routes/homework.py`.

## 12. Ограничения прототипа (назови сам — комиссия оценит)

1. Mastery — простое сглаживание, не BKT/IRT.
2. Пароли — SHA-256.
3. RAG — numpy в памяти, не pgvector при больших объёмах.
4. Профиль в RAM + батчинг — один воркер.
5. Зависимость от внешнего LLM (задержка, лимиты, стоимость).

**Перспективы:** bcrypt, pgvector, байесовский трекинг знаний, мобильное приложение, интеграция с ЭЖД.

## 13. Вопросы комиссии — короткие ответы

| Вопрос | Ответ |
|--------|--------|
| В чём новизна? | Замкнутый цикл персонализации + агенты + LLM + RAG + ролевые кабинеты |
| Настоящие ли ИИ-агенты? | Программные агенты; LLM — для генерации и семантики |
| Как адаптивность? | `topic_mastery` → слабая тема → `generate-adaptive-task` |
| Зачем RAG, если есть GPT? | Дешевле, привязка к учебнику, меньше выдуманных тем |
| Что такое CORS? | Браузер разрешает фронту с другого домена читать ответ API |
| Что такое RBAC? | Доступ по ролям; ученик не видит чужие данные |
| Почему FastAPI? | API, async, Pydantic, автодокументация |
| Почему профиль в JSON? | Гибкость; минус — сложная SQL-аналитика внутри payload |
| Что если LLM упал? | Каскад провайдеров, сообщение пользователю, фолбэк в ErrorAnalyzer |
| Готовый продукт? | **Прототип**, развёрнутый в облаке для демонстрации |

## 15. Пять фраз перед выходом на защиту

1. Цель — цикл «задание → профиль → следующий шаг».
2. Агенты координируются оркестратором; LLM — для текста и сложной классификации.
3. Адаптация: mastery по темам, порог 0.7, генерация по слабой теме.
4. RAG: эмбеддинги + поиск; админ наполняет базу знаний.
5. Ограничения прототипа знаем и называем сами — это сила, не слабость.
