# Маршрут изучения проекта AdaptEd - Построчное объяснение

## 🎯 Цель
Этот документ проведет вас через весь проект построчно, объясняя каждый кусочек кода и его назначение.

---

## 📋 Общая структура проекта

```
AdaptEd/
├── backend/          # Backend на FastAPI (Python)
│   ├── app.py        # Точка входа сервера
│   ├── models/       # Модели данных
│   ├── routes/       # API endpoints
│   ├── agents/       # AI-агенты
│   ├── services/     # Бизнес-логика
│   └── utils/        # Утилиты
└── frontend/         # Frontend на React/TypeScript
    ├── src/
    │   ├── main.tsx  # Точка входа React
    │   ├── App.tsx   # Главный компонент
    │   ├── components/  # UI компоненты
    │   └── services/    # API клиенты
```

## 🚀 МАРШРУТ ИЗУЧЕНИЯ

### ЭТАП 1: Точки входа (Entry Points)

#### 1.1 Backend Entry Point: `backend/app.py`
**Почему начинаем отсюда:** Это первая точка, которая запускается при старте сервера.

**Что изучаем построчно:**
1. Импорты и зависимости
2. Загрузка переменных окружения (.env)
3. Инициализация FastAPI приложения
4. Настройка CORS (Cross-Origin Resource Sharing)
5. Подключение роутеров (маршрутов API)
6. Базовые endpoints (/ и /debug)

**Время:** ~15-20 минут

---

#### 1.2 Frontend Entry Point: `frontend/src/main.tsx`
**Почему начинаем отсюда:** Это точка входа React приложения.

**Что изучаем построчно:**
1. Импорт React и ReactDOM
2. Создание корневого элемента
3. Рендеринг главного компонента App
4. Подключение стилей

**Время:** ~5 минут

---

### ЭТАП 2: Главные компоненты приложения

#### 2.1 Frontend: `frontend/src/App.tsx`
**Почему это важно:** Это главный компонент, который управляет всей логикой приложения.

**Что изучаем построчно:**
1. Импорты компонентов и сервисов
2. Состояния (state) приложения:
   - `isAuthenticated` - авторизован ли пользователь
   - `currentUser` - текущий пользователь
   - `currentRole` - роль (student/teacher/admin)
   - `showProfile` - показывать ли профиль
   - `loading` - состояние загрузки
3. Хук `useEffect` для проверки авторизации при загрузке
4. Функция `checkAuth()` - проверка токена
5. Функция `handleLoginSuccess()` - обработка успешного входа
6. Функция `handleLogout()` - выход из системы
7. Функция `handleRoleSwitch()` - переключение ролей (для админа)
8. Условный рендеринг:
   - Экран загрузки
   - Компонент авторизации
   - Основной интерфейс с header и контентом
9. Header компонент с навигацией
10. Переключение между дашбордами (Student/Teacher/Admin)

**Время:** ~30-40 минут
