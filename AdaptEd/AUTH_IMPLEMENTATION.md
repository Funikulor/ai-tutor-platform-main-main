# Полноценная система авторизации

## ✅ Что реализовано

### Backend

1. **Интеграция с БД PostgreSQL**
   - `AuthService` теперь работает с таблицей `users` в БД
   - Fallback на `persistent_storage` если БД недоступна
   - Автоматическое создание администратора при первом запуске

2. **Полноценная авторизация**
   - Регистрация пользователей (student, teacher, parent, admin)
   - Вход с токенами
   - Проверка токенов через middleware
   - Выход из системы

3. **Профиль пользователя**
   - Endpoint `/auth/profile` - полный профиль с аналитикой
   - Endpoint `/users/{user_id}` - профиль конкретного пользователя
   - Интеграция с аналитикой адаптивного педагога

### Frontend

1. **Страница авторизации**
   - Вход и регистрация
   - Проверка доступности backend
   - Красивый UI с обработкой ошибок

2. **Переключение ролей для админа**
   - Админ может переключаться между видами: Ученик, Учитель, Админ
   - Сохранение выбранной роли в localStorage
   - Индикация текущего режима просмотра

3. **Профиль пользователя**
   - Компонент `UserProfile` с отображением всех данных
   - Редактирование профиля (готово к расширению)
   - Отображение аналитики (если есть)
   - Кнопка выхода

## 🎯 Использование

### Для обычных пользователей

1. Зарегистрируйтесь через форму регистрации
2. Войдите в систему
3. Используйте платформу согласно вашей роли

### Для администратора

1. Войдите как админ (`admin@adapted.ru` / `admin123`)
2. В шапке сайта появятся кнопки переключения ролей
3. Нажмите на нужную роль (Ученик/Учитель/Админ) для переключения вида
4. Нажмите на аватар для просмотра профиля
5. Нажмите на иконку выхода для выхода из системы

## 📋 API Endpoints

### Авторизация

- `POST /auth/register` - Регистрация
- `POST /auth/login` - Вход
- `POST /auth/logout` - Выход
- `GET /auth/me` - Текущий пользователь
- `GET /auth/profile` - Полный профиль с аналитикой

### Пользователи

- `GET /users/{user_id}` - Профиль пользователя

## 🔄 Переключение ролей (только для админа)

Администратор может переключаться между ролями для:
- Тестирования интерфейса разных ролей
- Проверки функциональности
- Демонстрации возможностей платформы

**Важно:** Это только изменение вида интерфейса, реальная роль пользователя остается `admin`.

## 📊 Профиль пользователя

Профиль включает:
- Основную информацию (имя, email, телефон, класс)
- Роль и статус
- Дата регистрации
- Аналитику (если есть) - взаимодействия, точность тестов и т.д.

## 🗄️ База данных

Все пользователи сохраняются в таблице `users`:
- Автоматическое создание при регистрации
- Хеширование паролей (SHA-256)
- Уникальные email и user_id
- Поддержка всех ролей

## 🔒 Безопасность

- ✅ Пароли хешируются
- ✅ Токены для авторизации
- ✅ Проверка прав доступа
- ✅ Защита от SQL-инъекций (ORM)
- ✅ Валидация данных (Pydantic)
